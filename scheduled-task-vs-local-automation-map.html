Scheduled Task và Local Automation Map: quan hệ, khác biệt, khi nào dùng gì

Scheduled Task không phải một phương án cạnh tranh với Local Automation Map — nó là cơ chế trigger (đánh thức theo lịch) mà Local Automation Map dùng ở Stage 5 trong quy trình 6 bước của mình. Trang này đối chiếu 2 cách dùng: tạo thẳng 1 Scheduled Task, so với đi hết quy trình 6 bước rồi mới gắn vào Scheduled Task.

SCHEDULED TASK vs LOCAL AUTOMATION MAP

Quan he: Scheduled Task la co che trigger (cron hoac chay 1 lan) danh thuc 1 phien Claude
de chay 1 prompt. Local Automation Map la quy trinh 6 buoc (interview -> SPEC.md -> build
script/RUNBOOK/AI judgment -> dry-run/test -> git commit -> cau hinh Scheduled Task ->
verify/handoff), trong do Scheduled Task chi la co che trigger dung o Stage 5.

Khac biet chinh:
- Logic xu ly moi lan fire: Scheduled Task tran de Claude tu suy luan lai tu dau; Local
  Automation Map cho buoc co API chay bang local script co dinh, chi buoc can phan doan moi
  de Claude suy luan.
- Dedup: Scheduled Task tran khong co san; Local Automation Map bat buoc luu ID da xu ly.
- Retry khi loi mang: Scheduled Task tran tuy Claude; Local Automation Map bat buoc retry
  voi backoff trong code.
- Kiem thu truoc khi live: Scheduled Task tran khong bat buoc; Local Automation Map bat
  buoc dry-run truoc, chi chay that khi khop Acceptance.
- Version control: Scheduled Task tran khong co; Local Automation Map co git commit local.
- Approval khi fire: rui ro giong nhau o ca 2 - neu permission_mode khong phai auto, 1 action
  can duyet ma khong ai truc se lam phien dung giua chung.
- May can thiet: Scheduled Task tran mac dinh khong can may nguoi dung (chay tren cloud);
  Local Automation Map luon can may + Claude app + Chrome vi script/.env/git song tren do,
  nen phai khai bao "requires_local_device" va dung folder.
- Chi phi token: Scheduled Task tran ton token moi lan du viec lap lai y het; Local
  Automation Map chi ton suy luan o buoc AI judgment, phan script gan nhu free.
- Audit: Scheduled Task tran phai luc transcript; Local Automation Map co log ro tung buoc
  + README ghi san 3 dieu can check khi loi.

2 lo hong ky thuat can luu y:
1. Gioi han tan suat toi thieu (~1 gio) co the mau thuan voi vi du "polling moi 5 phut" ma
   prompt goc Local Automation Map dua ra cho truong hop event-trigger. Kiem tra gioi han
   lich thuc te cua to chuc truoc khi build.
2. Prompt goc khong nhac gi ve viec khai bao "requires_local_device" + dung folder khi tao
   Scheduled Task o Stage 5. Bo qua buoc nay se khien task chay nhu 1 phien cloud thuan tuy,
   khong thay duoc script/repo/Chrome, va fail ngay lan chay dau.

Khi nao dung cai nao:
- Dung thang Scheduled Task: viec don gian, lich chay >= 1 gio la du, khong can dedup/retry
  chat, chap nhan Claude suy luan lai moi lan.
- Di full quy trinh Local Automation Map: viec lap lai thuong xuyen, can dedup, can log de
  audit, muon logic co dinh khong phu thuoc suy luan moi lan chay.

2 lỗ hổng kỹ thuật đáng chú ý

1. Giới hạn tần suất tối thiểu mâu thuẫn với ví dụ trong prompt gốc

Scheduled Task theo mặc định chỉ chạy tối thiểu mỗi giờ, trừ khi tổ chức bật riêng cho phép ngắn hơn. Prompt gốc của Local Automation Map lại lấy ví dụ "polling every 5 minutes" cho trigger dạng event. Nếu tài khoản không được cấp lịch dưới 1 giờ, chiến lược này không tạo được — nên kiểm tra giới hạn thật của tổ chức trước khi build hết Stage 1–4.

2. Thiếu khai báo "cần máy này" + đúng folder khi tạo Scheduled Task ở Stage 5

Muốn Scheduled Task chạy đúng script/.env/RUNBOOK/Chrome trên máy của bạn, lúc tạo phải khai máy cục bộ và đúng thư mục automation. Prompt gốc không nhắc bước này — bỏ qua sẽ khiến lần chạy đầu tiên fail vì không tìm thấy file, mà không rõ lý do tại sao.

Khi nào dùng cái nào

Dùng thẳng Scheduled Task

  • Việc đơn giản, không cần chạy dày hơn mỗi giờ
  • Không cần dedup/retry chặt chẽ
  • Chấp nhận Claude suy luận lại từ đầu mỗi lần, đổi lấy không cần viết code

Đi full quy trình Local Automation Map

  • Việc lặp lại thường xuyên, cần ổn định
  • Cần đảm bảo không xử lý trùng, cần log để audit khi sự cố
  • Muốn logic cố định, không phụ thuộc suy luận có thể lệch nhau giữa các lần chạy
